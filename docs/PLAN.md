# Plan and decisions

Create a fresh buildless, static application with browser-local preferences and bookmarks. No student identity, marks, contact details, analytics, external submission endpoint, currency conversion, or eligibility scoring. Sites provides owner-private access. Catalogue data is separate JSON, compiled into dist at build time. The personal 2029 explorer is a reference only and will not be modified.

1. Define stable, separately linked institutions, programmes, applicant routes, awards, deadlines and sources.
2. Research official pages in bounded regional batches; retain publication cycles and questions. Build a college/university vertical slice before expansion.
3. Implement grade-aware exploration, interests, combined filters, route detail, local shortlist, three-route comparison, deadlines, coverage and copyable corrections. Translate navigation/core labels; label English catalogue descriptions.
4. Validate data, run meaningful route/filter logic checks, check build and available browser infrastructure.
5. Commit source, package exact output, deploy a new owner-private Site and record access state. School access is a later, explicitly approved rollout.

Conservative assumptions: future entry year does not imply claims have rolled forward; unknown requirements never mean an exemption. Scholarship eligibility is not selection probability. Grade is a local navigation preference and never restricts browsing.
